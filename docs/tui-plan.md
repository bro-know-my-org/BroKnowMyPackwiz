# bkmpw TUI 第一版实施计划

状态：用户已批准实施全部七个阶段；实施中。2026-09-15 用户要求先挂起 Windows/macOS 测试；跨平台实现与 CI 配置保留，外平台标为未验证。当前继续 Linux 和功能验收。各阶段实际验证记录见 `tui-progress.md`。

## 1. 产品目标与已确定范围

- 面向整合包作者，尽量覆盖现有 CLI 的管理、检查、安装、模板准备和导出能力。
- Windows、Linux、macOS；键盘优先，支持鼠标点击、滚轮和可见快捷键提示。
- 入口建议为 `bkmpw tui [pack-root]`；省略目录使用当前目录，无有效整合包时进入打开/初始化界面。
- 原有 CLI 调用、退出码与 JSON 协议保持兼容；无参数启动行为先保持不变。
- 一次打开一个整合包；提供目录选择和最近打开。切换前必须完成或取消并处理当前队列。
- 第一版包括简体中文、英文，自动识别系统语言，可手动切换并保存。
- TUI 文案、表单校验和应用自身操作结果国际化；现有 CLI 文案、第三方错误和原始日志保持原文。
- 用户要求的全部功能是第一版交付目标；下述阶段是可审阅的落地顺序，不是缩减最终范围。

## 2. 页面与操作

主导航：文件、添加、整合包、任务、设置；底栏持续显示任务状态和当前可用操作。

| 页面 | 第一版能力 |
| --- | --- |
| 文件 | Mods / Resource Packs / Shader Packs；搜索、过滤、排序、多选；详情、来源、有效 side、pin、preserve、本地文件状态 |
| 添加 | CurseForge 搜索、分页、项目详情和版本/文件选择；GitHub 仓库链接与 Release/附件选择；直链与本地文件表单 |
| 更新 | 单项/批量查询，当前版本到候选版本的预览、勾选应用；直接更新快捷操作 |
| 整合包 | 初始化、检查、扫描、刷新、模板准备、本地安装/下载/同步、modlist、各类导出 |
| 任务 | 当前进度、日志、待执行队列、历史结果；取消等待任务、取消并回滚当前任务、处理恢复与冲突 |
| 设置 | 常用整合包配置、Minecraft/加载器、安装/扫描、API 与导出配置；语言、外部编辑器、最近打开 |

交互默认：Tab 切换焦点，方向键浏览，Enter 打开/确认，Space 多选，Esc 返回或关闭弹窗，`/` 搜索，`?` 帮助。
输入框获取焦点时不触发全局字母快捷键；鼠标提供同等操作入口。
小窗口折叠详情或切换单面板；尺寸不足时明确提示，不能溢出或崩溃。
支持中文输入、粘贴、Unicode 路径和宽字符对齐，不承诺所有终端模拟器具有相同 IME 行为。

## 3. 来源、更新和元数据语义

- CurseForge 第一版提供关键词搜索和文件列表，默认按整合包 Minecraft 与加载器筛选。
- 放宽兼容过滤需要显式操作；展示不匹配信息。必需依赖递归解析、去重、检测循环与冲突，预览确认后加入同一任务。
- 未解决的依赖/版本冲突阻止提交；必需依赖不能被静默漏掉。
- CurseForge 缺少 API key 时引导配置；遵循已有环境变量和项目配置优先级、`x-api-key` 请求方式。
- GitHub 支持指定仓库后选 Release 和附件；第一版不做 GitHub 仓库关键词搜索。
- 当前 CLI 没有 Modrinth 项目接入。Modrinth 项目链接解析及搜索属于后续范围；HTTP 文件直链按直链能力处理。
- 添加与更新默认只改元数据；可勾选同时下载，元数据与下载形成同一个可回滚任务。
- 更新预览是只读查询；固定候选文件身份及原元数据指纹，执行前重新校验。
- 排队期间原文件或配置改变，预览失效时暂停并要求重新预览，不静默换成另一个“最新版本”。
- 直接更新跳过交互式候选选择，但仍经过相同的计划、校验和事务执行路径。
- pin、preserve、目录 side 优先级及旧 `.pw` 兼容规则保持现有语义。
- 表单只修改目标字段，保留未知 TOML 字段和无关注释；常用字段包括名称、side、pin、preserve 和已有来源/导出配置。
- 高级编辑器编辑暂存副本；返回后校验、展示变更并通过事务保存。真实文件有外部改动时走冲突处理。

## 4. 命令覆盖

| 现有命令 | TUI 入口 |
| --- | --- |
| `inspect`, `list`, `scan`, `check` | 文件详情、扫描和检查报告 |
| `init`, `refresh` | 整合包初始化、刷新索引 |
| `add-curseforge`, `add-github`, `add-url`, `add-file` | 添加向导 |
| `add-resourcepack`, `add-shaderpack` | 添加向导中的资源类型 |
| `pin`, `unpin`, `remove` / `rm`, `update` | 文件列表单项/批量操作 |
| `download-files`, `sync`, `install-local` | 下载、同步、安装表单 |
| `install-files`, `install-files-headless`, `install-files-retry` | 安装任务及重试参数；别名不各占一个菜单项 |
| `prepare-pack`, `prepare-server` | 模板与服务端准备 |
| `modlist` | 清单生成 |
| `export-client`, `export-curseforge`, `export-server`, `export-server-installer` | 导出向导 |
| `hash` | 文件工具/详情中的哈希操作 |
| help / version | 帮助、关于 |

JSON 输出选项和 protocol-version 保留为 CLI/集成接口。
建议第一版工具自身升级仍通过 `self-update` / `update-self` 执行，TUI 关于页提供操作说明；不在运行中的 TUI 内替换自身可执行文件。
CDPR 特定脚本逻辑（例如项目完整性清单）不自动并入通用 TUI。

## 5. 队列与事务保证

- 一个串行写任务队列；浏览和平台搜索在后台独立执行，界面保持响应。
- 配置保存、元数据编辑、安装到其他目录、导出到其他位置也必须登记实际写入集合。
- 回滚单位为一个队列任务；此前已经成功的任务不回滚。
- 每个任务分为规划、准备、提交、成功；取消/失败进入回滚。日志区分请求取消、正在停止、正在回滚、已取消。
- 网络等待设置有限超时，在下载块、文件处理等边界检查取消；不承诺按键后立即结束。
- 暂存新内容，记录原文件备份和持久化事务日志；覆盖/删除前完成恢复信息记录。
- 正常取消在回滚完成后才报告完成并允许退出；取消与任务提交成功的竞争需要明确的提交完成点。
- 崩溃或断电后，下次打开先恢复未提交任务；恢复完成前禁止修改操作。
- 不保证外部程序看不到跨文件提交的中间状态。恢复保证以文件系统仍可用、备份及日志未被外部破坏为前提。
- 检测到外部修改，暂停任务或恢复，保留原备份、当前外部内容和任务新内容；不强制覆盖。
- 提供冲突列表、差异/路径信息和显式解决入口；解决前不继续写任务。
- 导出先在目标所在文件系统暂存，完成后替换目标；已有目标需要保留恢复能力。跨文件系统输出逐目标记账，不依赖跨盘 rename。
- 空间预检查、准备失败和恢复失败必须有明确状态；不能在磁盘空间不足时擅自删除唯一备份。
- 批量任务中任一项目失败，整项任务失败并回滚；不把部分成功标为任务成功。
- 失败或主动取消均暂停队列，用户查看结果后手动继续；存在未恢复事务或冲突时禁止继续。
- 等待中的任务可以取消；队列保存任务参数与版本化状态，不持久化 API key 等秘密。
- 重启保留历史和未执行队列，用户确认才继续；中断任务标为待检查，不能自动重跑。
- 当前会话关闭后不提供后台守护执行；退出需要完成当前任务或取消并回滚，可保存未执行队列。
- 用整合包/目标写锁避免支持该协议的 bkmpw 实例互相写入；共享写入口让 CLI 也尊重锁。其他进程仍通过指纹检测冲突。
- `download-files` 不清理无关文件；同步只处理已记录的托管文件，未入清单的手动 jar 必须保留。

## 6. 技术方案建议

- `ratatui + crossterm`，同一 `bkmpw` 二进制增加 TUI 入口。
- UI 事件循环与后台工作线程分离；不为界面刷新强行迁移整个核心到异步运行时。
- 核心提供操作计划、结构化事件、取消令牌、事务写入接口；CLI 与 TUI 使用各自展示适配器。
- 底层不得直接向全屏终端写进度或调用 UI 翻译；日志进入事件流。
- i18n 使用消息键和参数，先提供 `zh-CN` 与 `en`，缺失键回退英文；不通过匹配英文错误字符串翻译错误。
- 对应用自身错误增加稳定错误码/类型，在 CLI 边界保留原有文本表现，在 TUI 边界生成本地化消息。
- 建议使用 `toml_edit` 支持保留文档格式的目标字段编辑。
- 用户语言、最近目录等放系统用户配置目录；队列历史放用户状态目录并关联规范化整合包路径。
- 可恢复的文件备份和日志与事务目标建立持久关联，启动时先读取恢复信息；不能只靠进程内存保存路径。
- 保证正常退出、panic、启动失败、外部编辑器往返时恢复终端模式和光标。

已核查的核心缺口：

- `src/curseforge.rs:104` 的现有查询面向精确定位，需要新增多结果搜索、分页及文件列表。
- `src/update.rs:60` 起查询与写入耦合，需要拆分 preview / apply。
- `src/progress.rs:47` 起进度直接输出终端，需要事件与展示解耦。
- `src/config.rs:55` 有加载逻辑但缺少配套配置编辑器。
- 原有写入并非统一经过事务路径；需要逐操作审计实际副作用，不能简单包一层菜单就声明支持回滚。

## 7. 实施顺序与阶段验收

1. **界面骨架与国际化**：入口、终端生命周期、页面导航、只读文件列表/详情、搜索过滤、多选、鼠标、双语。
   验收：三平台可启动和退出，中文/窄窗口稳定，原 CLI 不回归。这是最小可独立审阅阶段，不代表最终交付。
2. **操作事件与事务基础**：统一事件/错误适配、取消、写锁、事务日志、替换/删除/创建恢复，先接一条元数据编辑路径。
   验收：该路径正常成功、取消、故障和冲突恢复均可验证；未适配写操作不在 TUI 中开放。
3. **持久队列与配置编辑**：任务状态机、重启恢复、队列暂停继续、目录选择/最近打开、表单及高级编辑器。
   验收：重启不自动重跑、恢复阻塞修改、外部改动不被覆盖、TOML 无关内容保留。
4. **来源与更新流程**：CurseForge 搜索/文件/依赖；GitHub、直链、本地添加；更新预览与直接更新。
   验收：依赖闭包、兼容过滤、冲突阻止提交、过期预览、批量回滚和双语结果正确。
5. **下载、安装与同步**：接入进度、重试、取消和事务；“元数据 + 下载”组合任务。
   验收：网络失败、取消、校验失败均不留下半成品；旧文件可恢复，手动 jar 不受清理影响。
6. **模板、导出与完整覆盖**：准备整合包/服务端、各类导出、modlist、其余管理工具。
   验收：输出失败不破坏已有产物，多目标写入可恢复；完成命令覆盖逐项核对。
7. **发布验收**：三平台构建与终端烟测、语言与键鼠矩阵、故障注入及现有 CLI 回归。

阶段依赖：1 与核心基础设计可独立推进；3 依赖 2；4 的写操作依赖 2/3；5/6 全部依赖事务机制。
每阶段进一步拆成可审阅改动，非机械变更原则上不超过 800 行，复杂逻辑改动控制在 500 行以内。
事务骨架、调用方迁移与 UI 页面分开提交；不以一个巨大补丁交付全部第一版。

## 8. 验证与完成标准

- 每次代码交付执行 `cargo fmt --check`、`cargo test`、`cargo build --release`；CLI 烟测用 release 二进制。
- 事务测试在实际临时文件树中验证创建、替换、删除、多个目标、任一步骤失败和重复恢复。
- 覆盖取消/提交竞争、恢复过程再次中断、外部改动、磁盘/权限错误和任务队列损坏的处理。
- 队列状态机验证串行写入、暂停、取消、持久化、重启确认和预览失效。
- CurseForge/GitHub 使用可控响应验证分页、版本筛选、依赖循环、冲突和网络错误；真实联网烟测单列。
- 中文/英文资源完整性检查；输入框粘贴、多字节删除、焦点快捷键、长文本、滚轮与尺寸变化测试。
- Windows/macOS/Linux 分别构建，并做真实终端键鼠、中文输入、外部编辑器与终端恢复烟测。
- 当前环境不能执行的平台验收明确标为未完成，不能把交叉编译或单平台测试当作全部平台通过。
- 最终交付必须满足全部已选功能；未完成阶段、未经验证的平台或回滚路径明确列出，不以骨架冒充完整 TUI。
